## 0. 변환 원칙

1. **구조만 차용, 표현은 전부 우리 것.** 접미사·섹션 순서 같은 골격은 참고하되, 문장·어순·어휘는 재작성.
2. **경쟁사의 위반 요소는 반드시 제거.** 과장광고 표현·URL 도어웨이·canonical 메인 고정·중복 이미지.
3. **우리 우위 10종은 확대.** JSON-LD 6종 / 콘텐츠 변형 / EXIF 유니크 / VIEW 연계 (네이버 플레이스는 사용 안 함, 2026-04-20).
4. **검증 가능한 기준치**로 전환. 애매한 "개선"이 아니라 임계값(n-gram 0.35·alt 중복 10%·LCP 2.5s)으로 수치화.

## 6-B. 이미지 원본 비율 ↔ 컨테이너 aspect-ratio 교차 검증 (2026-04-20 추가)

**문제 인식**: 초기 스캐폴드에서 컴포넌트 이미지 컨테이너 높이를 `h-32`·`h-40`·`h-48` 같은 **고정 픽셀**로 정하고, 이미지는 별도 파이프라인에서 1200×800 (3:2) / 1080×1440 (3:4)로 생성 → 컨테이너 비율과 원본 비율이 어긋나 `object-cover`가 상하/좌우 자르기. 계획서가 SEO 메타만 챙기고 **시각 품질은 L5 `/browse`·L6 `/benchmark`에서 뒤늦게 잡히게 설계**되어 있어 Phase 2-A까지 오는 동안 드러나지 않음. 8도 복제 시 동일 패턴 반복 위험.

**원칙 (모든 이미지 컨테이너 적용)**:
1. **원본 비율이 기준**. 이미지 생성 파이프라인이 1200×800 (3:2)이면 컨테이너는 `aspect-[3/2]`. 1200×630 OG면 `aspect-[1200/630]` 또는 `aspect-[120/63]`.
2. **`object-cover` 쓰려면 `aspect-[W/H]` 를 같이 명시**. 고정 `h-N` + `object-cover` 조합은 금지(원본 비율과 동일한 비율이 되는 예외만 허용, 주석 필수).
3. **`<img>` 에 `width`/`height` 속성 명시**. CLS 방지 + Lighthouse 스코어.
4. **이미지 원본 치수가 바뀌면** 컨테이너 `aspect-[W/H]` 동시에 업데이트(같은 PR). 생성 스크립트 파라미터와 컴포넌트 `className` 이 같은 비율을 참조하는 **단일 진실원(SSOT)** 로 유지.
5. **검증 (L4 추가)**:
   - `scripts/verify-seo.mjs` — 샘플 HTML 에서 `<img object-cover>` 중 `aspect-[]` 명시 없고 `h-N` 만 있는 패턴 적발 시 WARN.
   - 향후 확장: `scripts/verify-images.mjs` 에서 실제 파일 치수 수집 → 비율 매핑표와 대조해 FAIL.

**적용 완료 컴포넌트 (2026-04-20)**:
