# URL 키워드 확장 설계 문서 (경쟁사 모방 + 변형)

## Context

경쟁사 jianhomecare.com 분석 결과:
- 메인 도메인에 **72,212개 URL** 운영 (동당 60개 키워드 조합)
- 모든 URL이 **동일한 홈페이지 HTML**을 렌더링 (URL만 다름)
- 서브도메인 10개+ / 위성 사이트 1개+
- JSON-LD, H1/H2 키워드 등 기술적 SEO는 약함

우리 전략: **경쟁사의 큰 틀(URL 키워드 스패닝)을 따르되, 아래 변형을 적용하여 차별화 + 리스크 감소**

| 페이지 콘텐츠 | 72,212개 **전부 동일** | **동별 콘텐츠 변형** (해시 기반) |

| Meta description | 모든 페이지 동일 | **동+서비스 맞춤 설명** |

| 이미지 | 같은 이미지 | **CSS 필터 변형 + 향후 실제 사진** |

## 구현 아키텍처

### 파일 구조

```
src/data/
  url-suffixes.ts      ← 60개 URL 접미사 배열 (신규)
  blog-templates.ts    ← 기존 콘텐츠 변형 시스템 유지
  blog-posts.ts        ← URL 접미사 × 동 조합으로 전체 포스트 생성
  regions.ts           ← 지역 데이터 (변경 없음)
```

### 핵심 로직

```typescript
// url-suffixes.ts
export const urlSuffixes = [
  '변기막힘뚫는곳업체비용해결후기',
  '24시변기막힘뚫는업체비용해결후기',
  // ... 58개 더
];

// blog-posts.ts
for (const region of regions) {
  for (const dong of region.districts) {
    for (const suffix of urlSuffixes) {
      posts.push({
        slug: `${dong}${suffix}`,
        city: region.city,
        // 콘텐츠는 suffix에서 서비스 타입 감지 → 해당 템플릿 사용
        // Title/Description은 dong + suffix 키워드 반영
      });
    }
  }
}
```

### 콘텐츠 렌더링 전략 (경쟁사 방식 + 변형)

경쟁사: 모든 URL → 동일한 홈페이지 HTML
우리: 모든 URL → **서비스 타입별 템플릿** + **동별 변형** + **동적 Title/Description**

| 요소 | 경쟁사 | 우리 |
|------|--------|------|
| HTML 본문 | 72,212개 전부 동일 | 서비스 타입별 3~4개 변형 |
| Title | 모든 페이지 동일 | `{dong} {suffix에서 추출한 키워드}` |
| Description | 모든 페이지 동일 | `{dong} {서비스} 전문가가 24시간 즉시 출동` |
| H1 | 모든 페이지 동일 | siteConfig.seo.h1 (이미 키워드 포함) |
| Keywords 메타 | 거의 동일 | dong + 서비스타입별 동적 생성 |

## 이미지 전략

### 현재 (Phase 1)
- CSS 플레이스홀더 + 색상/아이콘 변형 (이미 구현됨)
- 15개 blog-content 이미지 해시 기반 순환

### 향후 (Phase 2)
- 무료 상업용 이미지 사이트에서 배관 작업 사진 수집
- 또는 실제 작업 사진 촬영
- 이미지별 CSS filter 변형 (hue-rotate, brightness)
- ALT 태그는 동+서비스별 고유 텍스트 (이미 구현됨)

### 위성 사이트 이미지 (별도)
- 위성 사이트마다 **완전히 다른 이미지** 필수 (네이버 AI 유사 이미지 탐지)
- 좌우반전, 색감 변경도 잡힘 → 실제 다른 사진 사용

15,060개 URL → sitemap 인덱스 파일 필요:

- 또는 수동으로 sitemap-1.xml ~ sitemap-N.xml 분할

## 수정 파일 목록

| # | 파일 | 작업 |
|---|------|------|
| 1 | `src/data/url-suffixes.ts` | **신규** — 60개 URL 접미사 배열 |
| 2 | `src/data/blog-templates.ts` | suffix에서 서비스 타입 감지 로직 추가 |
| 3 | `src/data/blog-posts.ts` | URL 접미사 × 동 조합 생성 로직 |
| 4 | `src/app/[city]/[slug]/page.tsx` | slug에서 서비스 타입 감지 → 동적 Title/Desc |

## 검증 방법

1. `npm run build` → 15,060+ 페이지 빌드 성공 확인
2. 같은 동, 다른 suffix의 Title이 다른지 확인
3. 경쟁사 URL과 우리 URL을 나란히 비교 → 순서가 다른지 확인
4. sitemap.xml에 15,060개 URL 모두 포함 확인
