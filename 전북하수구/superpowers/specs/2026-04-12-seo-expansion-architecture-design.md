## 2. 전체 아키텍처 구조

```
[전략 계층 구조]

🏠 메인 사이트 (하수구막힘)
├── 전라북도 753개 블로그 포스트 (현재 완료)
├── 향후: 서울/경기/충청 등 전국 확장
└── 위성 사이트들과 백링크 연결

🛰️ 위성 사이트 3~5개 (향후)
├── 각각 다른 디자인/테마
├── 지역 특화 단일 페이지
├── 메인 사이트로 자연스러운 링크
└── Netlify 무료 배포

🔗 링크 흐름
├── 위성 → 메인: 풋터/CTA에서 자연스러운 앵커 텍스트
├── 메인 → 위성: 블로그 관련 링크로 연결
└── 위성 ↔ 위성: 절대 금지 (PBN 탐지 방지)
```

## 3. 메인 사이트 확장 전략

### 3.1 지역 확장 로드맵

| Phase | 지역 | 예상 포스트 수 | 시기 |
|-------|------|:---:|------|
| **Phase 1** (완료) | 전라북도 14개 시/군 | 753개 | 현재 |
| **Phase 2** | 전라남도 22개 시/군 | ~1,500개 | 다음 |
| **Phase 3** | 충청도 (충북+충남) | ~2,000개 | 이후 |
| **Phase 4** | 서울/경기/인천 | ~5,000개 | 장기 |

### 3.2 확장 방법

`regions.ts`에 지역 데이터만 추가하면 자동 생성:

```typescript
// regions.ts에 추가만 하면 끝
{
  city: '광주광역시',
  districts: ['동구', '서구', '남구', '북구', '광산구', ...동 목록],
},
```

### 3.3 콘텐츠 품질 관리

현재 템플릿 시스템의 한계:
- 동 이름만 바뀌고 본문 구조가 동일 → Google 중복 콘텐츠 리스크

개선 방향:
1. **템플릿 변형**: 서비스 타입별 5개 → 10개 이상의 콘텐츠 변형 추가
2. **지역 특화 콘텐츠**: 도시별 특성 (인구, 건물 연식, 주요 아파트 등) 삽입
3. **계절별 콘텐츠**: 겨울 동파, 여름 악취 등 시즌 키워드 추가
4. **실제 후기 데이터**: 실제 작업 사례를 데이터로 관리하여 삽입

## 4. 위성 사이트 전략

### 4.1 목적

- 메인 사이트의 도메인 권위(DA) 강화
- 지역별 키워드 추가 점유
- 검색 결과 페이지에서 다중 노출

### 4.2 계획

| # | 사이트명 | 타겟 | 디자인 |
|:-:|---------|------|--------|
| 1 | `jeonju-drain.netlify.app` | 전주시 하수구막힘 | 다크 테마 |
| 2 | `jeonbuk-toilet.netlify.app` | 전북 변기막힘 | 블루 테마 |
| 3 | `jeonju-sink.netlify.app` | 전주 싱크대막힘 | 그린 테마 |

### 4.3 안전 원칙

- 각 위성 사이트마다 **다른 디자인** 사용
- **고유 콘텐츠** 2,000자 이상
- 위성끼리 **상호 링크 금지** (메인으로만)
- **다양한 앵커 텍스트** (브랜드 30%, 키워드 25%, URL 20%, 일반 25%)
- 1~2주 간격으로 하나씩 배포 (자연스럽게)

## 5. 기술 아키텍처

### 5.1 파일 구조

```
src/data/
  regions.ts          ← 지역 데이터 (시 → 동 목록) - 여기만 수정
  blog-templates.ts   ← 3개 서비스 템플릿 + 자동 생성 함수
  blog-posts.ts       ← generateBlogPosts() 호출 (1줄)

src/app/
  layout.tsx          ← 글로벌 메타 + RSS link + JSON-LD
  page.tsx            ← 홈페이지 + BreadcrumbList
  [city]/[slug]/page.tsx  ← 블로그 포스트 + Article/Breadcrumb JSON-LD
  robots.ts           ← AI봇 차단
  sitemap.ts          ← 전체 URL 자동 사이트맵
  feed.xml/route.ts   ← RSS 피드

src/config/
  site.ts             ← 사이트별 설정 (도메인, 전화번호 등)
```

### 5.2 빌드 성능

| 포스트 수 | 빌드 시간 (예상) |
|:---:|:---:|
| 753개 | ~2초 |
| 3,000개 | ~8초 |
| 10,000개 | ~30초 |
